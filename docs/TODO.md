## 一、 音频元数据 (Metadata) 读写与管理

### 1. 全字段物理读写引擎升级（无 Rust 路线，待定选型）
> 现状：当前使用的三方预编译插件仅暴露了基础字段，无法写入作曲人、作词人、发行商等扩展标签。未来将在以下两种无 Rust 路线中权衡决策：

- [ ] **候选方案 A：自研纯 Dart 原生标签读写引擎（零外部依赖，极致轻量）**
  - **设计思路**：利用项目已有的二进制解析与字节处理基础，开发专用的纯 Dart ID3 (v2.3/v2.4)、Vorbis Comment (FLAC/OGG) 读写模块。
  - **优势**：
    - 100% 纯 Dart，完全自研自控，彻底摆脱第三方库各种低级 Copy-Paste Bug。
    - 零外部进程调用，执行速度极快，无需系统安装或应用捆绑 FFmpeg。
  - **考量点**：需按音频格式逐步实现二进制 Tag Block 规范（可优先实现市面上 90% 以上占比的 FLAC 和 MP3）。

- [ ] **候选方案 B：基于已有 FFmpeg 的流拷贝重写方案（全格式覆盖，开箱即用）**
  - **设计思路**：复用项目中现有的 FFmpeg 二进制环境，使用流拷贝（`-c copy -metadata key=value`）进行秒级重写。
  - **优势**：天然支持全音频格式（MP3, FLAC, M4A, OGG, Opus, WMA, WAV, APE, DSF 等），原生支持任意自定义标签与扩展属性。
  - **配套机制**：结合 `file_service.dart` 的 `replaceFileAtomically` 原子安全替换文件，保障掉电或中断不损坏源文件。
  - **考量点**：需依赖本地 FFmpeg 环境（现阶段依托 Windows 路径与 PATH 探测机制）或捆绑可执行文件，涉及子进程开销。

- [ ] **综合选型或混合路线评估**：
  - 届时可评估采用“**自研纯 Dart 处理主流格式（FLAC / MP3），FFmpeg 仅作为特殊格式兜底**”或直接单方案落地的可行性。

### 2. 批量元数据编辑 (Batch Editing)
- [ ] 支持在列表中多选音频文件，批量统一修改专辑名称、主要艺术家、发行年份、流派或光盘编号。
- [ ] 批量标签预览与差异高亮展示。

### 3. 封面管理与在线搜刮
- [ ] 添加本地封面图片更换、拖拽导入与直接导出保存到本地文件。
- [ ] 添加在线获取歌曲标签与高清封面功能（例如集成网易云/MusicBrainz API：`https://music.163.com/api/search/get/?s=<关键词>&limit=<数量>&type=1&offset=0`）。

### 4. 彻底解耦第三方解析库缺陷
- [ ] 现状：第三方纯 Dart 库 `audio_metadata_reader` 存在 FLAC/OGG “语言 = 艺术家”的低级 Copy-Paste Bug（ReMusic 现已加入拦截过滤防线）。
- [ ] 规划：未来评估以 FFmpeg probe 或轻量纯 Dart Vorbis/ID3 解析器统一读取源，避免三方库的脏数据污染。
